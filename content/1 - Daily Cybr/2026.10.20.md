# LOG · 2026-10-20

## Signal
> Source (KEV / advisory / link):https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-96951
> Product & version: Microsoft Windows Shell
> Why this one today (one line): It tackles with a command injection in a Windows context (which I'm currently learning)

## Stratum
> Vulnerability class: Command Injection / Security Bypass
> Layer where it lives: Windows Shell (User Interface)

## Descent
*Root cause, in my own words (max 3 sentences, no copy-paste):*

- In a certain command injection, shell mishandle special elements in the command (the input)

*How it is exploited, step by step:*

1. The attacker exploit this vuln with a malicious file. (so their payload isn't detected as suspicious because motw is bypassed)
2. Send it to someone bypassing MotW (the security that checks if a file from the internet is safe), so no warning when opening it !
3. The user have to be persuaded to open the malicious file

## Seal
*How it is fixed, and how a defender would notice it:*

- **Fix**: (CWE-77), the fix isn't well specified inside Microsoft October 2026 security update. Claude suggests that the generic fix pattern is "to never pass untrusted strings to a command interpreter. Use structured APIs or argument arrays, plus allowlists."

- **Detection**: Again this isn't specified, but here are some general options of detection for this kind of vuln:
	 
     **Patch compliance**: check build numbers against the fixed versions above.
	 
	 **MOTW presence**: downloaded files should carry a `Zone.Identifier` alternate data stream. You can inspect it with `Get-Item <file> -Stream *`. Files from the internet that lack it are suspicious.
	 
     **Process lineage**: hunt for unexpected child processes (script hosts, `cmd`, `powershell`) spawned from Explorer shortly after a user opens a freshly downloaded file.
