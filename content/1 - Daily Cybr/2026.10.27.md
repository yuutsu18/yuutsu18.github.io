## Walk through 

The goal is to exploit the XSS vulnerability in this site to get access to `/flag.txt`.

Firstly, we assume this will be a XSS reflected, because it is a root-me challenge and no user seems to exists.

Let's begin by cooking the script:
To be transparent, i don't know much about JS so i was assisted by AI to make it (and most importantly understand every line of it).
Here is the idea: The script has to open a new http request while not reloading the browser, then, use the GET http method to "get" the flag.txt file (don't forget to indicate `false` so that it doesn't run in the background and sync with the pdf maker). Finally it has to actually send this request and write the result in the rendered PDF.

<script>
x = new XMLHttpRequest; // create the xml http request
x.open('GET','file:///flag.txt', false); // select the GET method and ask for the flag while syncing with the pdf renderer
x.send(); // send the request to the server
document.write(x.responseText)); // writes the response in the PDF file
</script>

We try to inject the payload in the main input field (the message) unauthenticated to see how it works: everything is normal

Then, we see the sign up and login options: we try signing in to see the difference between unauth and auth:

![[Pasted image 20261027181132.png]]

We see that our first and last name is processed by the server, it seems like a better place to try our payload.

![[Pasted image 20261027182519.png]]

Something in our payload is wrong -> the format of the flag breaks everything -> let's encode it so we can decode it later (in base64 for example)

We ask our assistant how to add this in the script:

<script>
x = new XMLHttpRequest;
x.open('GET','file:///flag.txt', false);
x.send();
document.write(btoa(x.responseText)); //here "btoa" encodes the response in base64
</script>

To be transparent again, the AI proactively advanced the btoa solution to me and skipped the discovery that you have to do that. (I had to redo the challenge)

## Seal

- Fix: Sanitize dangerous special characters such as `<`,`>`,`&` in inoffensive ones. 
  We can also put rules that tell to the browser to never execute scripts that originates from a user input (Content Security Policy).
